# SOC Investigation Report

## Overview

This investigation demonstrates the analysis and correlation of Windows endpoint telemetry collected within an isolated SOC monitoring lab.

Native Windows Security auditing and Sysmon were configured on a Windows 11 endpoint to provide visibility into authentication activity, process creation, command execution, DNS activity, privilege use, account management, and security policy changes.

Controlled administrative activity was generated to validate the logging configuration and simulate the type of endpoint telemetry a SOC analyst may encounter during an investigation.

The objective was to identify relevant security events, analyze their context, correlate activity across multiple telemetry sources, and reconstruct endpoint activity using Windows Event Viewer.

---

## Investigation Objectives

The investigation focused on answering the following questions:

1. Can successful and failed authentication attempts be identified?
2. Can executed processes and command-line arguments be reconstructed?
3. Can parent and child process relationships be identified?
4. Can PowerShell activity be detected and analyzed?
5. Can DNS activity be observed through enhanced endpoint telemetry?
6. Can multiple event types be consolidated to support timeline analysis?

---

## Telemetry Sources

### Windows Security Log

Native Windows Advanced Audit Policy was configured to provide security-relevant telemetry.

Events analyzed during the investigation included:

| Event ID | Description | Investigation Use |
|----------|-------------|-------------------|
| 4624 | Successful Logon | Identify successful authentication activity |
| 4625 | Failed Logon | Identify unsuccessful authentication attempts |
| 4688 | Process Creation | Identify executed processes and command-line activity |

### Sysmon

Sysmon was deployed to supplement native Windows logging with enhanced endpoint telemetry.

Events analyzed included:

| Event ID | Description | Investigation Use |
|----------|-------------|-------------------|
| 1 | Process Create | Analyze processes, command lines, parent processes, users, and hashes |
| 22 | DNS Query | Observe DNS activity generated by endpoint processes |

---

## Authentication Analysis

Windows Security Event ID 4624 confirmed successful interactive authentication to the monitored endpoint.

The event provided information including:

- Account name
- Account domain
- Logon type
- Logon ID
- Authentication timestamp

Event ID 4625 was also generated through a controlled failed authentication attempt.

The event exposed additional investigative information including:

- Targeted account
- Failure reason
- Status and sub-status codes
- Logon type
- Originating workstation

Together, these events demonstrate how Windows authentication telemetry can be used to distinguish successful access from failed authentication activity.

---

## Process and Command-Line Analysis

Windows Security Event ID 4688 was used to identify processes created on the endpoint.

Process creation auditing captured information including:

- User context
- New process name
- Creator process
- Process command line
- Process identifiers

Controlled execution of administrative utilities demonstrated that command-line activity could be reconstructed from the Security log.

PowerShell execution was also examined. A child PowerShell process was launched with command-line arguments and subsequently identified through Event ID 4688.

This demonstrated how an analyst can identify not only that PowerShell executed, but also the command supplied to the process and the process responsible for launching it.

---

## Sysmon Process Analysis

Sysmon Event ID 1 provided additional context for process execution.

The telemetry included:

- Process image
- Command line
- Parent process
- Parent command line
- User context
- Process identifiers
- SHA-256 hash information

The PowerShell activity observed through Windows Security Event ID 4688 was independently observable through Sysmon process telemetry.

This demonstrates the value of combining native Windows auditing with enhanced endpoint monitoring.

---

## DNS Analysis

Sysmon Event ID 22 was used to validate DNS query monitoring on the endpoint.

Observed DNS telemetry included:

- Query name
- Query status
- Query results
- Associated process information

DNS monitoring provides useful investigative context because suspicious processes frequently rely on domain resolution before communicating with external infrastructure.

During testing, DNS Event ID 22 telemetry was successfully observed. A controlled `nslookup` process was separately captured through Windows process creation auditing; however, a corresponding Event ID 22 for that specific controlled lookup was not conclusively identified.

This distinction is retained to ensure the investigation accurately represents the observed telemetry.

---

## Event Correlation

A custom Windows Event Viewer view was created to consolidate:

- Event ID 4624 — Successful Logon
- Event ID 4625 — Failed Logon
- Event ID 4688 — Process Creation

This provided a centralized view of authentication and process activity.

Rather than reviewing each event type independently, the custom view allowed activity to be examined chronologically and provided a starting point for endpoint triage.

The investigation demonstrated a basic SOC workflow:

**Authentication Activity → Process Execution → Command-Line Analysis → Enhanced Sysmon Telemetry → Event Correlation**

---

## Findings

### Finding 1 — Authentication Auditing Operational

Successful and failed authentication activity was captured through Windows Security auditing.

**Security relevance:**  
Authentication telemetry provides visibility into account access and can support detection of repeated authentication failures, unauthorized access attempts, and unusual logon behavior.

### Finding 2 — Command-Line Process Auditing Operational

Windows Event ID 4688 successfully captured process creation and command-line information.

**Security relevance:**  
Command-line telemetry provides analysts with significantly more context than process names alone and can help identify suspicious administrative utilities, scripts, and command interpreters.

### Finding 3 — Enhanced Sysmon Telemetry Operational

Sysmon successfully generated enhanced process and DNS telemetry.

**Security relevance:**  
Sysmon supplements native Windows logging with additional endpoint context useful for threat hunting and incident investigation.

### Finding 4 — PowerShell Activity Observable Across Telemetry

PowerShell process activity was observable through Windows Security auditing and Sysmon.

**Security relevance:**  
PowerShell is a legitimate administrative tool but is also frequently relevant during security investigations. Visibility into process relationships and command-line arguments helps analysts distinguish expected administration from potentially suspicious execution.

### Finding 5 — Event Correlation Improves Investigation Efficiency

Combining authentication and process events into a custom investigative view provided a more efficient method of reviewing endpoint activity.

**Security relevance:**  
Correlating events chronologically can help analysts reconstruct activity and identify relationships that may not be obvious when reviewing individual logs separately.

---

## Conclusion

The investigation successfully demonstrated the collection, validation, and analysis of security-relevant Windows endpoint telemetry.

Native Windows Security auditing provided visibility into authentication and process activity, while Sysmon supplemented those logs with enhanced process and DNS telemetry.

By generating controlled activity and examining the resulting events, the lab demonstrated practical skills in:

- Windows event analysis
- Authentication monitoring
- Process and command-line analysis
- PowerShell monitoring
- Sysmon telemetry analysis
- Event correlation
- Timeline reconstruction
- Endpoint investigation

The resulting environment provides a foundation for future detection engineering, centralized SIEM ingestion, alert development, and more advanced incident-response exercises.
